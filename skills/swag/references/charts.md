# Charts

Identify the audience's question, source data, units, and intended comparison before selecting a chart. Use the runtime's installed `dataviz` skill when present. Read that copy and its applicable references before choosing encodings or writing chart code. Preserve its author, source, and license information when crediting the work. This is an optional runtime dependency; swag does not select or install a public package merely because it shares that name.

If dataviz is unavailable, say so and apply the chart principles here with the appropriate plotting or authoring tool. Its absence does not block an otherwise supported chart task. Do not claim that dataviz ran.

Match the encoding to the comparison. Keep axes, scales, baselines, units, and category order honest. Distinguish missing data from zero, preserve uncertainty, and avoid implying precision the source lacks. Use color according to the data's categorical, ordered, or diverging meaning, with sufficient contrast and distinctness.

Keep titles and annotations faithful to what the data supports. Label measures and units clearly, provide a plain-language legend for encodings, and retain sources and relevant assumptions. All permitted values and essential detail must remain available without making the main view overwhelming.

For an interactive chart, keep focus, selection, and details accessible without covering the data. For a static chart, make the finding and supporting evidence readable without hover. A chart in a document, slide, image, or web interface also follows that surface's delivery guidance.

Verify plotted values and scales against the data, then inspect the exact render or export at delivery size. Check small labels, long categories, missing values, legends, and color-independent interpretation. Exercise interactions separately when present. A beautiful screenshot is not evidence that the numbers are correct.
