# Documents and Markdown

Organize the reading path around the reader's question and next action. Use semantic headings, a consistent type hierarchy, readable measure, and deliberate spacing. Formatting should expose the structure of the material.

Keep substantive text editable and selectable when the format supports it. Preserve meaningful links, captions, sources, and the relationship between labels and content. Move supporting detail into connected notes or appendices rather than compressing or dropping it.

Let tables, code, and long names wrap or flow across the available space. Keep headings with the material they introduce, and preserve readable pagination and margins in print. Markdown must remain understandable in source form and in the target renderer.

Use the host's installed authoring and rendering specialist for the requested format when available. Preserve an existing template's intent and use its styles consistently. The specialist owns file construction, export, and format-specific verification.

Inspect the rendered document or target Markdown view. For paginated work, inspect every exported page for overflow, broken tables, orphaned headings, and missing content. Verify links and reading order where the format supports them. Source inspection alone does not establish export quality.
